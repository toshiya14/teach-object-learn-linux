## 第 1 页｜开场（0:00–1:00）

大家好，上一课我们已经把 Ubuntu 装进虚拟机了。现在你能看到桌面，也能打开终端。但可能还有个疑问：我在窗口里打几个字，电脑为什么就知道要做什么？

今天我们就沿着这个问题，认识 Linux 里面的几个角色。你不用背复杂定义，也不用拆电脑。我们先用生活里的比喻建立印象，再亲手运行几个命令，看系统怎样回应我们。

【操作】展示标题页，确认学员已进入 Ubuntu。终端暂时不用输入命令。

## 第 2 页｜学习目标（1:00–2:00）

【动画】按第 1–5 项依次展示目标。

今天主要记住几件事：内核负责什么；Shell、bash 和终端有什么关系；为什么 Linux 说“一切皆文件”；鼠标操作和命令行有什么不同。最后，我们会用三个命令完成四部分小实验。

听起来名词不少，但每个名词都有一个生活比喻。下课时，你能用自己的话说清楚它们的大概作用，就达到今天的目标了。设备文件名不用全背，更不用今天就学会改系统设置。

【互动】“你现在更习惯用鼠标，还是用文字命令操作电脑？”请一两位学员回答后过渡到内核。

## 第 3 页｜内核是系统的发动机（2:00–5:00）

【动画】先显示发动机比喻，再显示内核定义、硬件和示意图。

想象你坐进一辆汽车。你看到的是方向盘、踏板和仪表盘，但真正让车动起来的，是里面的发动机。Linux 也有这样的核心，叫内核，英文是 Kernel。

内核不负责把桌面画得好看，它主要管理硬件和资源。CPU 是执行计算的部件；内存是程序工作时临时存放数据的地方；硬盘用于长期保存文件；网卡负责网络通信。多个程序同时运行时，内核要协调谁先用 CPU、谁能用多少内存，以及怎样访问设备。

比如，你一边开浏览器，一边听音乐，电脑没有要求你手工给两个程序排队。这些资源协调工作，就有内核参与。现在先记住一句话：内核是系统核心，负责管理硬件和资源。

【互动】“浏览器要播放声音，是自己随便控制硬件，还是通过系统提供的服务？”

【参考回应】通过系统服务。实际路径可能还包括其他程序，今天先建立这个基本认识。

【停顿】让学员复述“内核像发动机”。然后指向图中的 Shell：我们怎样把要求表达给系统呢？

## 第 4 页｜Shell、bash 和终端（5:00–7:00）

【动画】依次展示翻译官、命令解析、bash、终端。

Shell 可以理解为翻译官。更准确地说，它是一个解析命令的程序。你按一定规则输入命令，它可以执行自己的内置功能，也可以启动别的程序；需要系统资源时，再通过内核提供的接口请求服务。

这里的“翻译官”是比喻，不是说我们随便输入一句中文，它就能理解。等会儿我们要输入的是固定的命令名称。

bash 是一种 Shell，就像浏览器有不同品牌，Shell 也有不同种类。本课程统一使用 bash。终端则是你输入文字、看到结果的窗口，背景不一定是黑色。终端像接待窗口，Shell 像窗口里处理请求的人，它们不是同一个东西。

【互动】“bash 是一种终端，还是一种 Shell？”等学员回答“一种 Shell”。

【过渡】普通程序和内核之间还有一道重要的分界，我们简单看一下。

## 第 5 页｜用户态与内核态（7:00–8:00）

【动画】按银行比喻、用户态、内核态、分层目的依次显示。

可以把普通程序活动的地方想成银行大堂，把内核工作的地方想成受保护的金库。普通程序运行在用户态，不能随便直接碰硬件；需要系统服务时，要按规定的方式请求内核。

内核运行在内核态，有管理硬件所需的特权。这种分层有助于安全和稳定，但不是电脑绝不会出故障的保证。

再提醒一句：用户态和内核态，不等于普通用户和管理员。管理员启动的普通程序也在用户态。这两个词今天听懂大概意思就够了，不需要背底层过程。

## 第 6 页｜“一切皆文件”是什么意思（8:00–9:00）

【动画】依次展示文档、目录、设备入口、系统信息。

平时说文件，你可能想到照片和文档。Linux 把文件的访问方式用到了更多地方：目录也是特殊的文件系统对象，许多设备有文件形式的入口，系统运行信息也能通过文件形式查看。

这就像很多不同部门都设置了服务窗口。窗口背后的事情不一样，但你能用相似的方式接触它们。等会儿我们会看两个地方：`/dev` 提供设备入口，`/proc` 提供系统运行信息。

“一切皆文件”是一个设计思想的概括，不是说硬盘变成了一篇文档，也不是所有入口都能随便读写。今天我们只列出名字，不向这些地方写入内容。

## 第 7 页｜图形界面与命令行（9:00–10:00）

【动画】依次展示鼠标操作、文字命令、共同目标和按钮说明。

图形界面，简称 GUI，就是通过窗口、图标和鼠标操作。命令行，简称 CLI，就是用文字命令表达操作。两者都能请求系统完成任务。

图形界面的按钮背后可能直接调用程序功能，不一定执行一条 Shell 命令。我们学习命令行，是因为命令容易记录、复现，今后还能用来批量处理事情。日常使用时，你照样可以用鼠标，两种方式可以配合。

【操作】切到终端。通常可以按 `Ctrl + Alt + T` 打开；若快捷键不同，从应用列表打开终端，请以实际版本为准。

【提醒】实验前建议使用已有快照；按虚拟化软件支持的方式保存。下面的命令无需管理员权限，请按示例原样输入。

## 第 8 页｜演示与跟练：echo（10:00–12:30）

【动画1】先解释：`echo` 用来回显文字，也就是把给它的文字显示出来。

先看我输入。命令后面有一个空格，再写要显示的文字。双引号用英文输入法里的符号。终端前面原有的提示符不是命令的一部分，不用抄进去。

【动画2／操作】教师输入并按回车：

```bash
echo "你好，Linux"
```

【动画3】看到输出后解释：

```text
你好，Linux
```

文字出现了，双引号没有显示，因为这里双引号是组织输入的符号，不是要输出的内容。bash 通常用内置的 `echo` 完成这件事，输出时使用系统服务，并不是把整条命令交给内核解析。

【跟练／停顿约 1 分钟】请学员输入同一条命令，再运行实验 A 中的对照命令：

```bash
echo 你好
```

这条也能输出“你好”。中文本身不要求加引号；给整段文字加英文双引号，是一个便于保留空格的好习惯。

【检查】若输入后出现 `>` 而不是预期输出，可能是引号没有闭合。按 `Ctrl + C` 取消本次输入，再重新输入。

## 第 9 页｜演示与跟练：whoami（12:30–14:30）

【动画】先显示命令含义，再显示示例；输出说明留到执行后。

第二个命令是 `whoami`，可以理解成“我是谁”。它显示当前有效用户的用户名，也就是系统此刻用哪个用户身份执行操作。

【操作】教师输入：

```bash
whoami
```

这里显示的是我的用户名。你的输出可能与我不同，正常登录、没有切换身份时，通常就是安装系统时设置的用户名。这里要看的是账号名，不是桌面上显示的昵称。

【跟练／停顿约 1 分钟】请学员运行并记下输出。幻灯片上的“你的用户名”是说明，不是要求电脑输出这五个字。

【互动】“为什么系统需要知道我们是谁？”引导回答：后面判断能否访问某个文件时，会用到用户身份。

## 第 10 页｜演示与跟练：ls /dev（14:30–17:30）

【动画】先说明 `/dev`，再显示代码，执行后说明设备名。

接下来用 `ls` 列出目录里的名字。命令中的 `/dev` 是一个路径，路径可以理解为系统里的地址。开头的斜杠表示从根目录这个起点出发；今天先照着输入，后续课程再详细讲路径。

【操作】教师输入：

```bash
ls /dev
```

现在看到一大串名字。先不用背，我们只找三个常见入口：`tty` 和终端有关；`null` 像一个黑洞设备；`zero` 是能提供零值数据的虚拟设备。今天只认识名字，不演示写入。

硬盘也可能出现在这里，但名称因配置不同，可能叫 `sda`、`vda` 或 `nvme0n1`。请以实际版本和虚拟机配置为准。你没看到 `sda`，不代表系统装错了。

【跟练／停顿约 1 分钟】学员运行命令，记录实际看到的三个设备文件名；可优先找 `tty`、`null`、`zero`。

【风险提醒】设备文件是访问设备的入口，写入某些磁盘入口可能破坏整块磁盘的数据。我们只执行这条列出名字的命令。

## 第 11 页｜演示与跟练：ls /proc（17:30–20:00）

【动画】先介绍运行信息，再显示代码，执行后展示虚拟文件说明。

最后看 `/proc`。这里提供系统运行时的信息，可以把它想成系统摆出来的一块实时信息板。

【操作】教师输入：

```bash
ls /proc
```

里面通常有 `cpuinfo`、`meminfo`，分别与 CPU、内存信息有关。还有很多数字目录，数字通常对应进程编号。进程就是正在运行的程序实例，今天只认识这个词。

我们目前只是列出名字，还没有读取文件内容。这些入口来自内核提供的虚拟文件系统，不是普通地保存到硬盘上的文档。运行状态改变时，部分条目也会变化。

【跟练／停顿约 1 分钟】请学员运行并记录两个实际看到的文件或目录名。

【互动】“`/dev` 和 `/proc` 各让我们看到了什么？”参考回答：设备入口和系统运行信息入口。

## 第 12 页｜完成四部分实验记录（20:00–25:00）

【动画】依次显示 A/B、C、D 和操作提醒。

前面我们已经边看边练了，现在给大家五分钟，把实验记录补完整。实验是 A 到 D 四部分：A 回显文字，B 查看用户名，C 找三个设备文件，D 观察系统信息入口。

【操作】展示实验手册中的记录表。

| 记录项目 | 填写要求 |
| --- | --- |
| `echo "你好，Linux"` | 记下实际输出 |

【互动约 2 分钟】请两位学员分享：一位说出终端与 Shell 的区别，一位说出设备入口和普通文档有什么不同。

【参考回应】终端负责输入输出，Shell 处理命令；设备文件是访问设备的入口，不是保存文章的普通文件。记录里的设备名可以不同，以实际输出为准。

## 第 13 页｜排错、小结与作业（25:00–30:00）

### 25:00–26:30：常见错误

如果出现 `command not found`，意思是没有找到这条命令，先检查拼写和大小写。比如 `echo` 要小写，不能写成 `Echo`。

如果输出很多名字，通常是正常的，不要求全部记住。如果用户名和老师不同，也正常。如果输入后一直等着你继续输入，先看英文引号是否成对；按 `Ctrl + C` 可以取消当前输入，再来一次。

### 26:30–28:30：回顾提问

【动画】按小结四项依次展示，每项先问再揭示。

我们用几个问题把今天串起来：谁负责管理系统资源？是内核。谁负责解析命令？是 Shell，bash 是其中一种。终端做什么？负责让我们输入命令、看到结果。

“一切皆文件”又是什么？它概括了 Linux 使用相似的文件访问方式处理许多对象的思想。设备和运行信息有文件入口，但不等于所有东西都是普通文档，也不等于能随意改写。

【互动】从小测验里口头抽问：“想显示当前用户名，应当用 `echo` 还是 `whoami`？”答案是 `whoami`。`echo` 只回显你给它的文字。

### 28:30–30:00：作业与下一课

课后请完成 A 到 D 四部分实验，保存截图；用自己的话说明 Shell 和终端有什么区别；记录三个设备文件名和你的猜测。再把 `whoami` 的输出与上一课学过的 `pwd` 输出记在一起：前者回答“我是谁”，后者回答“我在哪里”。

有余力的同学完成五题小测验，再对照文件末尾的答案。下节课我们认识桌面环境、快照与虚拟机管理，把快照理解成实验前的“存档点”，并了解第一次更新。今天先把这些角色分清楚，我们下节课见。
